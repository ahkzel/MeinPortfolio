Site web sur warhammer40k

Lien vers le code github

Site encyclopédique sur l'univers de warhammer 40k. Ce site présente des factions, personnages et planètes connues de cet univers et propose une boutique fictive. On peut s'y créer un profil de joueur, procéder à des achats dans la boutique et consulter les statistiques de cette dernière.

Le site est construit selon une architecture MVC avec une base de données mysql. Le fichier index.php va récupérer les méthodes $_GET, $_POST et les liens de la vue pour les envoyer en traitement aux contrôleurs. Le site est structuré avec un controleur par modèle ce qui signifie que certaines vues font appel à plusieurs contrôleurs. Il y a un modèle par table dans la base de donnée. Ces modèles récupèrent les données nécessaires aux contrôleurs qui les récupérent et les renvoient à la vue.

La base de données est composé d'une table factions, personnages, planètes, utilisateur, minifigs, joueur, et achat. Toutes les classes du site ne sont instanciées qu'une seule fois puis utilisées pendant l'utilisation du site et il n'y a pas de communication entre les contrôleurs.

Le site ne possède qu'un fichier css et un fichier js, tous deux plutôt optimisés.

Bot discord

Lien vers le code github

Projet réalisé en terminale codé intégralement en python. Il s'agit d'un bot ajoutable dans tout serveur discord proposant des fonctionnalités de modération, de chat, de musique (initialement), de roleplay et d'économie fictive.

Pour le coder, j'ai fais appel à l'api de discord et ses extensions, ainsi qu'asyncio et diverses API pour la musique telles que youtube_dl, youtube_dl2, spotify, etc. Malheureusement toutes les bibliothèques faciles d'utilisation en python sont obsolètes aujourd'hui principalement pour des raisons de droits d'auteur donc la partie musicale du bot ne fonctionne pas.

Il utilise une base de données composée de trois tables qui récupèrent les id des utilisateurs de discord et des serveurs afin de fonctionner en ligne sur plusieurs serveurs différents. Son code est organisé en POO pour accéder à ces bases de données et exécuter toutes les opérations qui ne sont pas relatives à discord. Pour ce qui est des commandes discord, celles-ci sont toutes implémentées dans le main, de même que sa connexion.

Jeu RP texte

Lien vers le code github

Ce jeu est mon premier projet en programmation. Il est codé intégralement en python sans utiliser d'API. Il ne possède pas d'interface utilisateur et n'est pas dynamique. C'est un script écrit qui est exécuté et des choix sont proposés à l'utilisateur tels que dans les "livres dont vous êtes le héro", on pourra des fois faire des choix mais tout est codé à l'avance.

Le projet est codé en POO et possède une classe : position, joueur, pnj, arme, armure, item, personnage, classe, et une classe héritière de la superclasse classe pour chaque classe spécifique.

Les objets des classes communiquent entre eux via des méthodes sans jamais appeler de getter et de setter afin de relier un personnage à son équipement par exemple, ou à sa position dans le monde.

Site web sur le cinéma

Lien vers le code github
Lien vers le site

Site web en html/css/javascript sur le cinéma. Le site possède une page d'accueil avec un formulaire et une barre de navigation pour naviguer entre les pages. Il possède une page renseignant différents sites de critiques visitables via des liens, et un input dans lequel on peut rentrer le nom d'un film, série, etc, qui va lier le résultat de cette barre de recherche aux liens des sites externes pour permettre d'aller directement rechercher sur tous les sites la série que l'on veut. Dans le code il y a un fichier html par page et un seul fichier css, le site est dynamique en partie mais il ne stocke rien, il n'y a donc pas de base de donnée, pas de compte utilisateur. Le changement de thème et la barre de recherche sont gérées par le script en javascript.

Installation Apache2

Télécharger le tuto

Installation d'apache2 à partir d'un tutoriel sur une VM debian linux neuve. Installation faite purement en lignes de commandes, installation d'apache puis configuration dans /etc/apache2 et utilisation des commandes propres à apache (systemctl restart apache2...)

Apache 2 est un serveur HTTP (sûrement le plus populaire). Apache sert donc à communiquer avec un navigateur en utilisant le protocole HTTP(S) pour mettre en place ses propres sites web, les héberger et il est souvent utilisé avec un serveur LAMP (Linux Apache MySql/MariaDb Php) afin d'accéder à des bases de données.

Installation LAMP OCS-GLPI

Télécharger le tuto

Installation d'un serveur LAMP OCS-GLPI sur une VM debian linux possédant apache2. Installation en lignes de commandes suivi sur un tuto avec l'installation complémentaire de MariaDB, Php, OCS et GLPI car l'installation d'apache2 était déjà faite.

LAMP ou Linux Apache MySql/MariaDb PHP est une pile logicielle qui permet de mettre en place un serveur web. Elle comporte un système d'exploitation, un serveur HTTP, un SGBD et un langage de programmation. Les 4 combinés permettront de communiquer avec le site web via le protocole HTTP(S), interpréter les requêtes et y répondre aux moyens d'un script, agissant sur le site en lui-même et sur la base de donnée dont les données peuvent être manipulées, supprimées et ajoutées.

OCS GLPI quant à eux sont des logiciels permettant d'inventorier le matériel et les logiciels d'un parc informatique via un navigateur internet et proposent une intégration de logiciels et de systèmes de ticketing.

Installation windows serveur 2022 AD-DNS-DHCP

Télécharger le tuto

Windows serveur est un système d'exploitation de serveurs développé par microsoft qui permet de gérer le réseau en général, nécessaire pour les entreprises. On peut s'en servir pour optimiser nos performances, créer des groupes de travail et de partage, gestion des utilisateurs et de leur identité, renforcer la sécurisation des données...

L'Active Directory est l'élément base de données qui met en lien les utilisateurs avec les ressources réseau dont ils ont besoin et leurs autorisations. Le serveur DNS va permettre de traduire les noms de domaine en adresses IP, nécessaire pour communique. Le serveur DHCP, lui, permet l'attribution de ces adresses IP aux utilisateurs du réseau.

Liaison windows serveur - GLPI

Télécharger le tuto

GLPI permettant une gestion web des utilisateurs, lier GLPI à un annuaire Active Directory permet une gestion centralisée de ces utilisateurs. C'est une façon de faciliter la mise à jour du réseau pour un être humain via l'interface de GLPI. En tout, GLPI permet une meilleure acccessibilité aux utilisateurs qui ont un identifiant unique pour se connecter à plusieurs système et une sécurité renforcée via la centralisation de la gestion.


Projets d'entreprise

Support utilisateur

En tant que TDs, notre but premier est de s'assurer que les artistes puissent travailler dans des conditions optimales et avoir accès à tout l'environnement de production. Chaque production requiert certains logiciels avec chacun sa version définie et certains packages avec chacun sa version définie. Cela pose souvent des conflits entre packages et logiciels car la version requise d'un logiciel peut ne pas être compatible avec la version requise d'un package, ou une prod peut évoluer et soudainement avoir besoin d'une mise à jour sur un de ses packages ou logiciels.

C'est le ticket de support que j'ai résolu ci-dessous. Nous avions besoin d'avoir la version 2025 de meshroom (un logiciel "maison") sur une prod mais cela a créé un conflit entre 2 packages déjà définis qui ne demandaient pas la même version de meshroom. Il a donc fallu les mettre à jour, puis une fois que le ticket était résolu j'ai envoyé un message à l'artiste concerné pour lui faire savoir que le problème était reglé.

Exporteur de caméra

L'exporteur de caméra est un projet que j'ai terminé en septembre 2025. Le but était de créer un exporteur de caméra pour prendre une caméra d'une scène houdini et l'exporter dans un autre logiciel ainsi qu'un baker d'animation pour créer une caméra de rendu sur une animation das houdini.

Le package est codé en python. Il possède un launcher qui appelle l'ui du baker ou de l'exporteur selon lequel on appelle via le menu de houdini, l'ui est écrite avec un wrapper de Qt maison et renvoie les informations entrées par l'utilisateur directement au core du code qui traite les données et exporte donc la caméra ou bake l'animation. J'ai réalisé ce projet en collaboration avec 2 de mes collègues notamment car les tests demandaient de créer artificiellement des prods ce qui a demandé de rajouter du code dans d'autres packages.

Sanity Check

Le sanity check est une application que j'ai mis en place dans nuke pour permettre aux artistes de faire une check liste de leur scène en vérifiant automatiquement si tout respectait les normes de production avant de l'envoyer en rendu.

Le package est codé en python et il existait déjà mais dans maya j'ai donc repris une partie du code déjà existant (dont l'ui). Le launcher du package cherche si celui-ci a été lancé depuis maya ou nuke et en fonction de la réponse il va setup les adapteurs pour créer l'application correspondante. Il renvoie ensuite à l'ui du sanity check et les informations utilisateurs sont renvoyées au core du code qui va appeler chaque check (qui sont des classes POO) pour le process.

Toolbox

La Toolbox est une application conçue par les artistes dans nuke maya et houdini qui répertorie tous les scripts écrits par les artistes pour chaque prod et chaque utilisateur et les exécute sur demande. Elle présente également une fonctionnalité pour créer un nouveau script directement à partir de l'application et pour afficher le chemin du script ainsi que son contenu.

Le package est toujours en cours d'écriture. Mon but est de réécrire le code écrit par les artistes, refaire l'architecture et refaire l'ui afin de pouvoir intégrer proprement le package dans le pipe. Pour l'ui j'ai créé des widgets personnalisés héritant de ceux de Qt et le reste du code a été clean après une architecture mvc. Le Launcher va demander depuis quel logiciel l'application a été lancée et appelle l'ui en fonction, puis toutes les actions effectuées dans l'ui sont redirigées vers le main qui s'occupe d'appeler les processus correspondant à chaque action dans le core du code.

Centraliseur de Menu

Le créateur de Menu (vfxDccToolkit) est un package qui centralise tous les menus que nous avons créés sur diverses packages pour chaque logiciel et qui les créé lui même. Il Permet de créer un menu à partir d'un simple fichier json et de le rajouter aux menus déjà existants.

Le package est codé en python à l'aide d'abstract class en POO. Le launcher regroupe tous les menus trouvés (script json et variables d'environnement) et appelle le créateur de menu adapté à chaque logiciel (nuke/maya/houdini) afin de les construire.

Wrapper de Qt

vfxMikGUI est un package que nous avons créé pour créer nos propres ui personnalisées pour l'entreprise plus facilement. Le wrapper créé une application Qt personnalisée et propose des widgets propres au package qui sont tous des widgets qui héritent de ceux de Qt avec des personnalisations spécifique à notre usage. Il suffit de rajouter un fichier dans le dossier "widgets" et de créer son propre widget et il devient utilisable partout dans le contexte de l'entreprise.

Le Package a été codé en python par un collègue mais je l'ai beaucoup utilisé lors de ces derniers mois que ce soit pour faire les ui des packages sur lesquels je travaillais ou pour y rajouter des widgets. Pour l'exporteur de caméra par exemple j'ai ajouté un widget FrameRange. Celui-ci créé une box avec 3 spinbox contenant les valeurs de la première frame, de la dernière frame et du step d'une animation.
